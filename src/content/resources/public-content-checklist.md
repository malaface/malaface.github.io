Usa esta lista antes de proponer una publicación técnica. Su propósito es reducir omisiones y hacer que la revisión sea consistente.

## Alcance y claridad

- [ ] El título describe un resultado o una pregunta concreta.
- [ ] La introducción explica para quién es el contenido y qué cubre.
- [ ] Cada sección contribuye al propósito declarado.
- [ ] Los términos técnicos se explican cuando aparecen por primera vez.

## Evidencia y autonomía

- [ ] Las afirmaciones se apoyan en fuentes públicas o resultados reproducibles.
- [ ] Las recomendaciones se presentan como recomendaciones, no como hechos universales.
- [ ] El texto conserva el contexto mínimo para entender cada decisión.
- [ ] Los ejemplos funcionan con datos ficticios y se pueden seguir de principio a fin.

## Protección del contenido

- [ ] No hay datos personales, detalles operativos ni información reservada.
- [ ] Los enlaces apuntan únicamente a destinos públicos intencionales.
- [ ] El documento no depende de material privado para tener sentido.
- [ ] La política automática de publicación termina sin violaciones.

## Calidad de entrega

- [ ] El frontmatter cumple el esquema de su colección.
- [ ] Las pruebas y la compilación terminan correctamente.
- [ ] La página se revisó en pantalla pequeña y grande.
- [ ] La fecha, los enlaces y el estado de publicación están actualizados.

Una checklist no sustituye el juicio editorial. Sí libera atención para revisar el argumento, la utilidad y la experiencia final con mayor cuidado.
